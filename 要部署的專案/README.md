# ⚠️ 這是「部署工作區」，不是你的原始程式備份

**這個資料夾裡的東西會被工具改動。** 請把你的原始程式保留在別的地方。

---

## 一句話說明

把你想上線的專案**複製一份**放進這裡，工具會在這裡重整結構、產生建置檔案、
加上設定檔，然後部署出去。原始資料夾請留在原處不要動。

```
你的原始專案資料夾          ← 真正的備份，工具不會碰
        │
        │ 你自己複製一份
        ▼
要部署的專案\<專案名>\      ← 這裡。允許被工具改動
        │
        │ 工具部署
        ▼
    公開網址
```

## 為什麼要複製一份，不直接用原始資料夾

部署過程會做這些事，都不適合發生在你的原始程式上：

- **重整目錄結構** —— 網站檔案要搬進 `public\` 子目錄（原因見下方）
- **產生建置產物** —— 例如 `dist\`、`node_modules\`，動輒數百 MB
- **加入設定檔** —— `project-hub.json`、`wrangler.jsonc`
- **刪除不該上線的檔案** —— 名單、`.env`、開發筆記等

如果直接對原始資料夾做這些，一旦出錯就沒有乾淨的版本可以退回。

## 你要放進來的東西

### 1. 專案本身（複製一份）

整個資料夾複製進來即可，資料夾名稱用中文也沒問題。

### 2. 網站首頁的截圖（選用，但建議放）

**放在專案資料夾的最外層**，和設定檔並列：

```
要部署的專案\我的專案\
  ├─ 我的專案截圖.png     ← 放這裡
  ├─ project-hub.json
  ├─ wrangler.jsonc
  └─ public\              ← 不要放這裡
```

- **檔名不限** —— `截圖.png`、`我的專案首頁.jpg` 都可以
- **比例不限** —— 畫面會完整顯示，不會被裁切
- **不要放進 `public\`** —— 那裡是網站內容，放進去會被當成網站的一部分公開
- **上限 1 MB**，建議壓到 500 KB 以內（縮圖在卡片上只佔一小塊，每個訪客都要下載它）。
  太大的話用「小畫家」開啟 →「重新調整大小」→ 改成 50%

沒放截圖也可以部署，展示中心的卡片會顯示「此專案尚無預覽圖」。
事後補的方法有兩個：到管理後台的「上傳圖片」按鈕，或是請 AI 執行
`node bin/hub.mjs thumbnail <專案代稱> <圖片路徑>`。

**縮圖存在資料庫裡，三條路徑都是存好就立刻生效**，不需要重新部署展示中心。

### 3. 只有網址的資料夾（網站已經在別的地方上線）

你以前用 Google 協作平台、Blogger 或別的服務做過的網頁，不需要也不應該從這裡
重新部署。這種情況資料夾裡**不要放網頁檔案**，只放一個寫著網址的文字檔：

```
要部署的專案\我的班網\
  ├─ 新增 文字文件.txt     ← 裡面貼上完整網址（https:// 開頭）
  └─ 截圖.png              ← 選用
```

文字檔的檔名不拘（右鍵新增文字檔得到的「新增 文字文件.txt」直接用就好）。
然後跟 AI 說「幫我把 `要部署的專案/我的班網` 加進展示中心」，
它會執行 `node bin/hub.mjs link`——只登錄，不部署、不推 GitHub。

放了 `index.html` 的話會被判成要部署的專案，那個指令會拒絕並叫你改用部署指令。

## 絕對不要放進來的東西

部署 = 把資料夾內容公開到網際網路上。以下東西放進來就會被公開：

| 不要放 | 為什麼 |
|---|---|
| `.env`、`.env.local` 等 | 環境變數檔，常含資料庫連線字串或金鑰 |
| `secrets.toml`、`*.pem`、`id_rsa` | 憑證與私密金鑰。外流無法靠改密碼補救 |
| 真實名單（學生、成績、聯絡資料） | 受個資法規範 |
| 教室或實作現場的照片 | **背景最容易夾帶資訊** —— 曾在白板照片右上角發現 Wi-Fi 密碼 |
| 開發筆記、對話紀錄、工作計畫 | 不影響執行，但會讓內部討論隨網站公開 |

**部署前一定會自動掃描這些，並在動手前列給你確認。** 但掃描只看檔名，
**圖片內容與 PDF 內文無法自動判讀** —— 現場照片請自己看過四個角落。

## 部署前先跑這個

在 Hub 專案根目錄執行（把路徑換成你的專案）：

```
node bin/hub.mjs check "要部署的專案\我的專案"
```

輸出分三級：

| 級別 | 意思 |
|---|---|
| **重大** | 失敗就不能部署，不會問你。把檔案移出資料夾再來 |
| **需確認** | 列出來並說明原因，你確認後才繼續 |
| **提醒** | 告知而已，不擋 |

「需確認」的項目，確認可以上傳的就把路徑逐行寫進專案資料夾裡的 `.hub-allow`
（一行一個相對路徑、`#` 開頭是註解），之後就不會再問同一個檔案。

## 為什麼網站檔案要放在 `public\` 子目錄

這是實測踩到的坑，不是潔癖：

1. **Wrangler 會把自己產生的暫存檔算進網站內容。** 若 assets 指向專案根目錄，
   `.wrangler\tmp\` 裡的暫存檔會被一起上傳，而且每次執行的檔案數都不一樣。
2. 根目錄還放著設定檔與截圖 —— 那些都不是網站內容，卻會被當成網站的一部分。

放進專屬子目錄後，設定檔與截圖留在外層，天然不會被上傳。
